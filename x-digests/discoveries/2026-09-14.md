## Investigate
- **Procedural Graphs framework for LLM agents**: Self-evolving structure using (procedure, relation, procedure) triplets to guide agents step-by-step, learning from successful/failed trajectories to repair priors without manual engineering. Outperforms memory baselines. Paper: https://paperswithcode.com/paper/2609.09153. Why interesting: Concrete new architecture for reliable agentic reasoning beyond simple memory or graphs. Next step: Read the full paper and related code if available; prototype a small example.
- **agent-orchestrator and multi-agent coding coordination**: Tool (12k stars) for managing parallel coding agents (Claude Code, Aider, OpenHands, etc.) with branching, merging, permission voting, session replay, conflict prevention. Addresses chaos in multi-agent setups. Why interesting: Shifts focus from single agents to production orchestration layers. Next step: Explore the GitHub repo, understand architecture, test with small tasks.
- **Model routing for LLM cost optimization**: Dynamic selection of models/providers based on task complexity/cost (e.g., cheap/fast vs. capable). Real-world wins (Uber 7x scale with stable costs), tools like DIT ai (50+ providers, one API), Ollama integrations. Why interesting: High-ROI production pattern with measurable impact; complements caching and other optimizations. Next step: Sign up/test DIT ai or implement simple router; measure cost savings on sample workloads.
- **Cross-application agent pipelines (e.g., creative/engineering tool chaining)**: Agents creating closed perception-action loops across tools like Inkscape → Blender (drafting, importing, meshing, self-evaluation/fixing). Related: generative AI studios that output full reproducible apps from workflow descriptions. Why interesting: Unexpected integrations bridging disparate software interfaces in non-obvious ways. Next step: Search for open implementations or examples of such agent loops; experiment with chaining tools via agents.
