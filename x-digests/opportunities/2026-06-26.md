## 🔬 Methodology Deep Dives

### 1. Claude Code as Full Agentic System (Deep Workflow Architecture)
**Source**: X thread https://x.com/i/status/2037978621684621428 (high-engagement 2026 guide on treating Claude Code as autonomous agent).
**What they built**: Production-grade agentic coding workflow using Claude Code with declarative configuration instead of ad-hoc prompting.
**Step-by-step methodology**:
- Create CLAUDE.md (root, git-committed, <200 lines): build/test commands, architectural decisions, naming conventions, gotchas, import styles. Loaded into every system prompt as persistent knowledge.
- CLAUDE.local.md for personal overrides (gitignored).
- rules/ folder with YAML-frontmatter scoped instructions (only loads relevant rules per path, e.g., API rules in src/api/).
- Skills: Reusable workflows in SKILL.md (YAML: name, description, when to activate, allowed tools). Example: security reviewer limited to read/grep/glob.
- Hooks: Deterministic shell scripts for PreToolUse, PostToolUse, Stop events (auto-lint, security gates like "never rm -rf", "tests must pass").
- Sub-agents: Isolated specialists (Explore read-only Haiku, Plan, General, custom) with configurable models/tools to prevent context pollution.
- MCP (Model Context Protocol): .mcp.json for external tool connections (GitHub, Slack, DBs, browser automation, Sentry).
- Memory: Persistent across sessions via ~/.claude/.
- Workflows: "Interview me" for clarifying questions; Research→Implement split; parallel worktrees; active context management (/clear, sub-agents, double-escape); Plan Mode before execution; permission whitelists.
**Tool stack & why**: Claude Code (core agent), sub-agents (isolation), MCP (integration), hooks/skills (reliability). Chose over pure prompting because it shifts to process design and delegation.
**Architecture decisions**: Declarative markdown configs as system prompts; modularity/scoping to fight context rot; Plan→Act→Verify loops with explicit evaluation.
**Mistakes fixed**: Overstuffing CLAUDE.md, no context clearing, skipping Plan Mode, ignoring sub-agents, poor isolation.
**Non-obvious insight**: The highest-leverage move is building *one excellent configured agent* (strong instructions + config files) before scaling to teams or adding complexity — declarative over imperative, isolation prevents quality drift. Others treat it as autocomplete; winners treat it as orchestration layer.
**What we can apply directly**: Adopt CLAUDE.md + skills/hooks pattern in Hermes/podcast-pipeline for reliable agent workflows; integrate MCP-style tool connections; prioritize Plan Mode + sub-agents for our automation cron jobs. Score: Novelty 4, Actionability 5, Depth 5, Relevance 5 (Total 19/20).

### 2. Multi-Agent Orchestration & Workforce Building
**Source**: https://x.com/i/status/2067888525953958155 (June 2026 guide on scaling from single agent to team).
**What they built**: Orchestrated multi-agent systems for research/write/code/review/ship while sleeping.
**Step-by-step**:
1. Master one excellent single agent in Claude Project (strong Role/Standard/Format/Boundaries).
2. Add handoffs (worker → critic loops); run manually first to refine.
3. Add tools via connectors/MCP (web search, files, APIs); keep human in loop initially.
4. Build Orchestrator that automates delegation, collection, critic routing, assembly (sub-agents or API).
5. Add reliability: evaluation suite, persistent memory, failure handling, loop limits.
**Tool stack**: Claude Projects + sub-agents/critics + MCP/tools.
**Architecture**: Orchestrator (manager) + Specialists (narrow/deep) + Critic/Reviewer (highest leverage). Explicit handoff protocols.
**Non-obvious insight**: Building agents forces you to clarify *your own process* first — vague processes = vague agents. Most skip the Critic role, leading to "fast garbage"; orchestration + critic turns outputs shippable.
**What we can apply**: Add critic loops and orchestrator pattern to our agent pipelines; start with single strong agent then layer. Score: Novelty 3, Actionability 5, Depth 4, Relevance 5 (Total 17/20).

### 3. Solo AI Agent Business Lessons (Verification-First Factory)
**Sources**: Multiple threads e.g. https://x.com/Voxyz_ai/status/2029167828373520870, https://x.com/levie/status/2039931799414194621, https://x.com/dhpwd/status/2069691748914487740.
**Key extracted methodology**:
- Don't map human org charts to agents (fewer agents with combined responsibilities; litmus test: remove agent, does downstream break?).
- Brutally delete scaffolding as models improve (build harness for current limits, then ruthlessly prune).
- Verification first: tests, CI, browser automation before anything else.
- Build bottom-up: verification → clean codebase → context/docs → specs → encoded skills → layered review.
- Ship ugly, charge early, solve your own bottlenecks, use smallest model that works, keep stack boring.
- Reliability obsession: watchdogs, auto-restore, proactive failure alerts.
**Non-obvious insight**: Scaffolding half-life is shrinking (months → weeks); the skill is organizational reflex to delete fast. Unit economics + reliability > model sophistication. Build the "AI software factory" in bottleneck order, not glamorous middle layers.
**What we can apply**: Prioritize verification gates and critic loops in our pipelines; ruthlessly simplify/delete old agent code; focus on our own bottlenecks first. Score: Novelty 4, Actionability 5, Depth 5, Relevance 5 (Total 19/20).

**Why it matters**: Moves beyond research demos (AutoGPT/OpenHands) to reliable digital workers delivering complete outputs (research, code, sites). Strong multi-provider (DeepSeek, Doubao, Kimi, OpenRouter) and MCP support.
**Composes with**: Claude Code/Cursor (bootstrap), existing MCP tools, skill libraries.

### 2. PilotDeck (OpenBMB / Tsinghua)
**What it does**: Task-oriented AI agent productivity platform / "agent operating system" with per-project isolated Workspace (filesystem, memory, skills) to prevent context bleed. White-box memory (inspect/edit/trace/pin), smart model routing, background long-horizon execution, MCP support, web UI, lifecycle hooks.
**Why it matters**: Production focus on inspectability, isolation, and reliability rather than flashy demos. AGPL-3.0.
**Composes with**: Any MCP-compatible agent, memory providers, our Hermes-style skills.
**Adoption signals**: Strong discussion in agent circles, active university-backed development.
**GitHub**: github.com/OpenBMB/PilotDeck. Score: Novelty 5, Actionability 4, Depth 4, Relevance 5 (Total 18/20).

### 3. LangBot
**What it does**: Universal deployment framework — build agent once, run across Discord/Telegram/Slack/WeChat/LINE/WhatsApp/etc. from single codebase. Integrates Dify/Coze/n8n/Langflow/DeerFlow; built-in RAG, multi-pipeline, access control, monitoring, plugin ecosystem. MCP server for programmatic extension. Docker one-command.
**Why it matters**: Solves "build once, deploy everywhere" for agent distribution and multi-channel access. MIT license, 15k+ stars, actively maintained.
**Composes with**: DeerFlow/PilotDeck agents, our pipelines, multiple frontends.
**GitHub**: Implied active repo (search github.com for LangBot agent). Score: Novelty 3, Actionability 5, Depth 3, Relevance 4 (Total 15/20).
