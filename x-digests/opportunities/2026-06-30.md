## 🔬 Methodology Deep Dives

### 1. Claude Cowork as Full Desktop Coworker (One-Person Company System)
**Source**: @sairahul1 (https://x.com/sairahul1/status/2070795168677265758 and thread)
**What they built**: A complete personal operating system turning Claude's desktop agent app (Claude Cowork) into an autonomous coworker handling 60%+ of repetitive knowledge work (emails, reports, decks, research, writing, SEO, file organization). Runs the company via high-judgment decisions while the system executes.
**Step-by-step methodology**:
1. Install Claude desktop app + paid Opus 4.6 plan.
2. Create root `Claude Cowork` folder pointed to by the app.
3. Inside it: ABOUT ME subfolder with `about-me.md` (thinking style, "good" standards — generated via voice interview), `anti-ai-writing-style.md` (banned phrases), `my-company.md` (north star, strategy, what to say no to); OUTPUTS folder for finished files; TEMPLATES folder (auto-save successful outputs by stripping content).
4. Set Global Instructions in app settings to always read ABOUT ME, use AskUserQuestion before starting, build plan + get approval, then execute and save to OUTPUTS.
5. Core reusable prompt (text replacement `/prompt`): “Read my ABOUT ME folder and global instructions. Use AskUserQuestion before starting. Build a plan, ask for approval, then execute and save to OUTPUTS.”
6. Use voice dictation (Wispr Flow) for richer context (3x better than typing).
7. Add Plugins/Specialists via SKILL.md folders for domain experts (e.g., weekly content writer with exact steps/quality checks). Use official Anthropic plugins (Marketing, Sales, etc.).
8. Add Connectors for Slack/Google Drive/Notion/etc. for live data.
9. Schedule automations (morning briefing, midday production, EOD wrap-up).
10. Token optimizations: restart conversations, batch tasks, use cheaper models for simple work, summarize sessions.
**Tool stack**: Claude desktop (Opus 4.6), voice dictation, folder-based context, AskUserQuestion forms, connectors, scheduled runs.
**Architecture**: Folder-driven persistent context (no session memory) + form-based clarification + specialist plugins + connectors + scheduled execution. Output lands in real files.
**Non-obvious insight**: The killer feature is not better prompts but `AskUserQuestion` (clickable forms/multi-selects) combined with explicit "legible" context files that make the agent behave like a consistent employee rather than guessing. Voice input + banned-style files eliminate generic AI output.
**What WE can apply directly**: Adopt identical folder architecture + global instructions + voice briefing for Hermes agents running on VPS. Add SKILL.md per agent profile. Score: Novelty 4, Actionability 5, Depth 5, Relevance 5 (Total 19/20).

### 2. Automated Development Software Factory (Multi-Agent Engineering Pipeline)
**Source**: Zach Lloyd (@zachlloydtweets, https://x.com/zachlloydtweets/status/2069789929073262945)
**What they built**: Internal "cloud software factory" where agents (not humans) primarily write code and ship; humans design/optimize the factory. Metric shifts to "% of changes shipped fully automatically" and factory efficiency (value shipped / inference cost + human time).
**Step-by-step methodology**:
1. Triage agent: Understands/reproduces issues, decides if fully automatable.
2. Spec agent (if ambiguous): Produces specs for human review.
3. Implementation agent: Writes the code.
4. Code review agent.
5. Verification agent (computer-use, tests, monitoring).
6. Human review only where necessary (goal: minimize over time).
7. CI/CD + ship.
8. Monitor agent: Closes the loop by creating new issues.
9. Every human intervention becomes data to improve the factory (self-improving loop). Treat automation as variable COGS.
10. Engineers' real job = meta-engineering: prompts/harnesses, self-improvement agents, ROI measurement on every factory dollar.
**Tool stack**: Multi-agent orchestration (LangGraph/CrewAI-style or custom), computer-use verification, CI/CD, monitoring.
**Architecture**: Sequential specialized agent pipeline with human exception handling + feedback loop into factory improvement. Recursive self-improvement is the long-term vision.
**Non-obvious insight**: Success is measured by automation percentage and cost efficiency, not features shipped manually. Interactive agents are treated as learning opportunities to reduce future human touch, not endpoints.
**What WE can apply directly**: Model Hermes cron jobs and agent profiles after the factory (triage → spec → implement → verify). Add monitoring agent that feeds back into opportunity scanner. Score: Novelty 4, Actionability 4, Depth 5, Relevance 5 (Total 18/20).

### 3. Making the Business "Legible" to Agents (Context Layer as the Company)
**Source**: Aggregated from Greg Isenberg, Aaron Levie, and solopreneur threads (e.g., https://x.com/gregisenberg/status/2070918939526205494)
**What they built**: Solo AI-agent businesses where the moat is a shared, always-fresh context layer (SOPs, decisions, memory, state, pricing, permissions) that agents can actually read and act on.
**Step-by-step methodology**:
1. Pick a painful sub-niche in a big market; document every daily workflow step manually first.
2. Highlight money-changing-hand points and repetitive vs. judgment tasks.
3. Quantify pain (hours saved × rate).
4. Create shared context files/SOPs for every process (agents get their own identity + knowledge base + state files).
5. Design workflows from scratch for agents (new entrants have advantage over legacy companies).
6. Build in public: post daily about workflow/learnings; use AI to generate content.
7. Start narrow, prove ROI, expand; add governance/verification for high-stakes work.
8. Keep context layer fresh as business evolves (hardest ongoing challenge).
**Tool stack**: Documentation systems, agent identities, persistent state files, public content loops.
**Architecture**: Company = legible shared brain (context/SOPs) that agents plug into; humans handle taste/strategy/judgment only.
**Non-obvious insight**: Documentation and context freshness become the primary competitive advantage (and moat) in 2026; most companies aren't even legible to their own staff.
**What WE can apply directly**: Treat x-digests, skill files, and Hermes profiles as the living "legible company" layer. Update cron jobs to refresh context. Score: Novelty 3, Actionability 5, Depth 4, Relevance 5 (Total 17/20).
