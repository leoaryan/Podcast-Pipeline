# Discoveries — 2026-08-13

## Investigate
- **BAML (Basically A Made-up Language)**: Purpose-built language for AI agents treating LLM calls as strongly-typed functions with schemas, enums, error handling, retries, tracing, and first-class evals/tests for non-deterministic behavior. Generates typed clients across many languages (Python, TS, Go, Rust, etc.). Incremental adoption possible. ~9K GitHub stars. Why interesting: Moves beyond fragile prompt→JSON cycles to reliable, composable AI system primitives. Suggested next step: Clone repo, explore docs/examples, implement a small typed extraction or workflow.
  Link: https://x.com/techNmak/status/2087040108382060688 (search for BAML GitHub)

- **Kimi Code CLI**: Open-source (MIT) Claude Code-style coding agent. Key features: accepts screen recordings as input, built-in coder/explore/plan subagents with separate contexts, automatic MCP server setup, plan mode before edits, integrations with Zed/JetBrains/VS Code. Ships as single fast binary. Why interesting: Practical multi-agent coding workflow with novel input and context management. Suggested next step: Install and test with a small coding task involving planning/subagents.

- **ratcn (for Ratatui)**: New library of themeable terminal UI components (dialogs, buttons, lists, selects, tabs, mouse/keyboard support) for Rust Ratatui. Focus on rich, good-looking TUIs without heavy frameworks. Why interesting: Concrete design philosophy for modern Rust CLI/TUI development alongside Clap. Suggested next step: Review source/examples, experiment building a simple TUI tool.

- **intpot framework**: Define tools once with @app.tool() decorator and expose as CLI, MCP server, or REST API. Promotes reuse across interfaces. Why interesting: Clever abstraction bridging different tool invocation patterns for agents. Suggested next step: Check implementation and see how it handles multiple exposure modes.

- **Semantic caching & hybrid deterministic+LLM workflows**: Discussions around 80%+ cost reductions via semantic caching repos, and extreme (99.5%) token savings using deterministic code/rails for most steps + LLM only on variable parts (tool result filtering, synthetic workflows). Why interesting: Production-grade cost/token optimization patterns with measurable impact. Suggested next step: Identify and inspect popular caching repo; prototype a hybrid workflow for a multi-step task.
