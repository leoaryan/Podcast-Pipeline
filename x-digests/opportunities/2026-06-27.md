## 🔬 Methodology Deep Dives

### 1. Narrow Scoping + 9-Step 2026 AI Agents Roadmap (@tyrtyre201, @DivyanshT91162 and community consensus)
**Source**: https://x.com/tyrtyre201/status/2066826145119588796 and https://x.com/i/status/2041355311358083095

**Who / What built**: Multiple solo builders shared consistent frameworks for moving from AI usage to reliable agent systems.

**Step-by-step methodology extracted**:
1. Define the Purpose — Identify a real problem, know your user, define exact expected output.
2. Structure Inputs & Outputs — Use JSON schemas, keep outputs predictable, design API-first.
3. Craft Better Prompts — Role-based, set tone/expertise, iterate continuously.
4. Add Reasoning + Tools — Multi-step thinking (ReAct-style workflows), connect APIs/databases/calculators.
5. Multi-Agent Collaboration — Planner → Executor → Checker pattern to scale complexity.
6. Memory & Context — Store conversations, use embeddings for long-term memory.
7. Multimodal (Optional) — Add voice, images, video for richer interactions.
8. Output & Delivery — Dashboards, reports, JSON — make it automation-ready and user-friendly.
9. Deploy & Monitor — APIs/UI integration, track performance.

**Tool stack**: ReAct-style loops, JSON schemas, persistent memory (embeddings or git/markdown), multi-agent orchestration, monitoring dashboards.
**Architecture decisions**: Start extremely narrow (one specific job at 95% reliability beats generic 40%). Strong planning/specs/rules before coding. Verifiable outputs required.
**Non-obvious insight**: The hardest part isn’t models or tools — it’s deciding what NOT to build. Vague scopes lead to abandonment; one-sentence problem definition + success/failure moment is the real bottleneck. Focused agents win.
**What WE can apply directly**: Enforce narrow scoping in all Hermes agent profiles. Adopt Planner/Executor/Checker patterns and JSON-structured I/O. Score our own agents on the 9-step checklist.
**Score**: Novelty 3/5, Actionability 5/5, Depth 4/5, Relevance 5/5 → **17/20**

### 2. CLAUDE.md / Agent Governance 12-Rule System (community expansion of Karpathy/Forrest Chang)
**Source**: https://x.com/i/status/2068197417506222428

**Step-by-step / rules extracted** (expanded 12-rule version):
- Original 4 (Think Before Coding, Simplicity First, Surgical Changes, Goal-Driven Execution) + new: No model calls for deterministic logic (routing/retry in code), hard token budgets, one agent per directory (Git worktrees), write PROGRESS.md checkpoints, fail loudly with specifics, unique skill descriptions, separate researcher vs implementation sessions, scoped hooks only.
- Keep the file short (<100–200 lines).
- Add project-specific sections for what not to touch and default success criteria (test passes + build succeeds + verifiable by something other than the model).

**Non-obvious insight**: Well-crafted rules files are the highest-ROI part of architecture for reducing error rates in unsupervised runs. Treating rules as the “operating system” for agents beats prompt engineering alone.
**What WE can apply directly**: Update Hermes profiles with expanded CLAUDE.md-style governance, add PROGRESS.md checkpoints, enforce hard token budgets and deterministic logic in code.
**Score**: Novelty 4/5, Actionability 5/5, Depth 4/5, Relevance 5/5 → **18/20**

## 🧱 Component Discoveries

### 1. Vercel eve
**What it does**: Filesystem-first TypeScript framework where an agent is a directory of files (`agent.ts`, `instructions.md`, `tools/`, `skills/`, `subagents/`, `schedules/`). Includes durable execution, checkpoints, sandboxing, human-in-the-loop, MCP + API integrations out of the box. Commands: `eve dev`, `vercel deploy`.
**Why it matters**: Treats agents like Next.js routes — opinionated production infrastructure baked in instead of wiring everything manually.
**Compatibility surface**: Composes with Vercel ecosystem, Next.js, TypeScript agents; supports Slack/Discord channels, cron schedules.
**Adoption signals**: Launched mid-June 2026, public preview, Apache 2.0, templates already appearing (personal-agent-template, content-agent-template).
**GitHub link**: https://github.com/vercel/eve
**Score**: Novelty 4/5, Actionability 4/5, Depth 4/5, Relevance 3/5 → **15/20**
