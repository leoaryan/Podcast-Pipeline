## 🔬 Methodology Deep Dives

**Pattern from multiple solo AI agent builders (synthesized from X threads on workflows and lessons learned, e.g. references to @gregisenberg, multi-agent office builders, content pipeline operators)**  
What they built: Persistent, self-improving multi-agent "offices" or content/ops systems running 24/7 on VPS with minimal human oversight.  
Step-by-step methodology extracted:  
1. Define clear specialist roles (e.g., Scout for research/keywords, Quill for writing with strict brand/SEO rules, Sage for editing with plagiarism/accuracy/Flesch gates, Publisher, Social amplifier, PM coordinator).  
2. Use shared database (Notion/Supabase) as single source of truth with status flows and atomic claim-locking to prevent race conditions in parallel agents.  
3. Implement heartbeat/cron every 5 mins; PM agent checks backlog/stuck items and spawns fixes.  
4. Add memory distillation: insights/lessons/strategies/preferences extracted from conversations/outcomes and fed back probabilistically (e.g., 30% influence on future behavior).  
5. Quality gates that reject ~40% of first drafts; circuit breakers, sandboxes per agent, auto-restore on crashes, alerts.  
6. Start with 3 agents (coordinator, executor, observer) before adding conversations/memory/initiative/affinity.  
Tool stack: Hermes/OpenClaw for base agent + messaging gateways (Telegram/Slack), Claude/Codex/Cursor for building, Composio for tools, structured policies/JSON in DB.  
Architecture: Layered (memory layer with bounded/curated files like MEMORY.md + USER.md + SQLite; execution loop Think→Plan→Act→Observe→Adjust with skill auto-generation after 5-15 tool calls; orchestration via cron + gateways).  
Non-obvious insight: Specialized agents + explicit constraints + orchestration > one generalist agent; reliability ("it just works" with watchdogs/self-healing) is the actual product that retains high-ticket customers ($2k–5k/mo), not flashy capabilities. Treat agents like employees with SOPs, performance reviews from outcomes, and memory of failures.  
What WE can apply directly: Enhance our Hermes profile with specialist agent swarms, claim-locking in shared state, and auto-skill generation loops for podcast pipeline tasks. Score: 16/20 (Novelty 4, Actionability 5, Depth 4, Relevance 3 — aligns closely with existing Hermes infra).

**Recurring self-improving agent loop (from Hermes-style and AutoAgent discussions)**  
What they built: Meta-agents or base agents that autonomously generate reusable skills/markdown artifacts capturing procedures/pitfalls/verification steps.  
Step-by-step: After complex tasks, auto-generate skill file; load it on next similar task for faster/better execution; meta-agent takes markdown description of desired behavior, iteratively rewrites prompts/tools/configs/routing, evaluates against benchmarks overnight.  
Tool stack: Hermes (persistent memory + skills), uv for Python envs, benchmarks like SpreadsheetBench/TerminalBench.  
Architecture: Closed learning loop on top of persistent memory + tool calling.  
Non-obvious insight: The compounding advantage comes from the agent remembering lessons and evolving "relationships"/affinity scores rather than pure reactivity; moving from static skill installation to dynamic auto-generation is the differentiator (why some switched from OpenClaw to Hermes).  
What WE can apply directly: Implement auto-skill extraction in our cron jobs and podcast pipeline for recurring tasks like research/synthesis. Score: 15/20.
