### 1. 8 Core Layers for Production-Ready AI Agents (Elora Khatun, @elora_khatun, June 2026)
**Source**: https://x.com/elora_khatun/status/2061630565972103214

**What they built**: A comprehensive blueprint treating agent building as systems engineering rather than prompt tweaking.

**Step-by-step methodology**:
1. Define the Purpose — Use case, user needs, constraints, success metrics (most projects fail here).
2. System Prompt Design — Treat prompts as the operating system (role, goals, instructions, guardrails).
3. Choose the Right LLM — Match model to task (e.g., GPT-5.5 for tool use, Claude for reasoning/long context).
4. Tools & Integrations — APIs, MCP servers, databases, custom tools.
5. Memory Systems — Working memory, vector databases, structured storage, episodic memory.
6. Orchestration — Workflows, triggers, queues, retries, routing, multi-agent coordination.
7. User Interface — Chat, APIs, Slack bots, dashboards.
8. Testing & Evaluations — Measure quality, latency, reliability, and hallucinations.

**Tool stack**: MCP for tools, vector DBs for memory, orchestration layers for workflows.
**Architecture**: Layered system where orchestration and memory sit above the model.
**Non-obvious insight**: AI Engineering = Software Engineering + Prompting + Systems Design + Automation. The people who master orchestration, memory, tools, and workflows will dominate — raw LLM choice is secondary.
**What we can apply directly**: Enforce the 8 layers in Hermes agent profiles; prioritize MCP and orchestration in all new skills. Score: 18/20 (Novelty 5, Actionability 5, Depth 4, Relevance 4).

### 2. Practical Agentic Coding Workflow / "My Setup" (Jack Culpan, @JackCulpan, March 2026)
**Source**: https://x.com/JackCulpan/status/2029478582352003150

**What they built**: Battle-tested orchestration prompt and file-based task system for Claude-style coding agents on real software projects.

**Step-by-step methodology** (key elements of the prompt/system):
- Default to Plan Mode for anything non-trivial (3+ steps or architecture). Re-plan immediately if things go wrong. Write detailed specs first.
- Subagent Strategy: Use them heavily to keep the main context clean. One task per subagent. Throw compute at research/exploration.
- Self-Improvement Loop: After *any* user correction, update `tasks/lessons.md` with the pattern. Review lessons at the start of every session. Ruthlessly iterate to reduce repeat mistakes.
- Verification Before Done: Never mark complete without proof (tests, logs, diffs). Ask: "Would a staff engineer approve this?"
- Autonomous Bug Fixing: Just fix it. Point to logs/errors and resolve without hand-holding.
- Task Management: Use `tasks/todo.md` with checkable items, progress tracking, high-level explanations, review sections, and lessons capture.
- Core Principles: Simplicity first, no laziness (find root causes), minimal impact changes, balanced elegance.

**Tool stack**: Claude (or equivalent), structured markdown files (todo.md, lessons.md), subagents.
**Architecture**: Plan → Execute with subagents → Verify → Self-improve via lessons file.
**Non-obvious insight**: The "plan mode default" combined with mandatory post-correction lessons capture creates compounding reliability; most agents repeat mistakes because they lack persistent, reviewable failure memory.
**What we can apply directly**: Implement `lessons.md` + plan-mode enforcement in our coding agents and opportunity-scanner itself. Score: 17/20 (Novelty 4, Actionability 5, Depth 5, Relevance 3).
