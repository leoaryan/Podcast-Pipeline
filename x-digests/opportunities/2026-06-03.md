## 🔬 Methodology Deep Dives

### 1. Greg Isenberg's Vertical AI Agent Playbook
**Who**: @gregisenberg, founder of Late Checkout
**Source**: x.com/gregisenberg/status/2058923630960988300
**Score**: 18/20 (Novelty: 4, Actionability: 5, Depth: 5, Relevance: 4)

**The Full Methodology (extracted)**:

1. **Domain immersion first**: Find a painful workflow in a boring industry. Interview real users. Map EVERY step, tool, spreadsheet, and phone call they make. "Be the agent before you build the agent."

2. **Manual execution phase**: Actually do the workflow yourself for 2-3 customers. This surfaces edge cases that would break an automated system. You discover that "obvious" steps aren't obvious at all.

3. **Knowledge base in Obsidian**: Document everything as structured markdown. This becomes the agent's memory and the training data for skills. The quality of your Obsidian vault determines the quality of your agent.

4. **Agent stack**: Hermes (orchestration harness) + Obsidian vault + Composio (tool authentication layer) + 1-3 core skills. Keep it minimal — don't build 40 agents before you need them.

5. **Ship free first**: Give the agent to first customers for free. Watch what they actually do with it. It won't be what you expected. The usage patterns tell you what to build next.

6. **Outcome-based pricing**: Charge per outcome (per lease renewed, per claim processed), not per seat. This aligns incentives and creates natural expansion revenue as customers use it more.

7. **Memory as moat**: Let the agent write to its own memory after every task. The accumulated context across customers becomes impossible to replicate. This is the defensibility.

8. **Model routing**: Smart expensive models for complex tool calls and decisions. Cheap/open-source models for lightweight tasks. Route dynamically based on complexity.

9. **Expand vertically**: Once you own one workflow step, expand to own the entire vertical OS. Stack multiple agents across customers. Margins are high enough that these businesses shouldn't raise VC.

**The Non-Obvious Insight**: The moat isn't the model or the code — it's the accumulated context and the Obsidian knowledge base. Every interaction makes the agent smarter for the next customer. Competing with this requires not just copying the code, but replicating months of domain-specific learning.

**What We Can Apply**: This is our blueprint. We already have Hermes, Obsidian, skills, and cron jobs. The missing piece is picking a boring vertical and doing the manual execution phase. Every component of this playbook maps to infrastructure we already own.

### 2. ECC (Everything Claude Code) — Agent Orchestration at Scale
**Who**: @affaan-m (Affaan Mustafa), solo developer
**Repo**: github.com/affaan-m/ECC
**Stars**: 150K-200K+
**Score**: 19/20 (Novelty: 5, Actionability: 4, Depth: 5, Relevance: 5)

**The Architecture (extracted)**:

1. **40-60 specialized agents**: Planner, security reviewer, debugger, code reviewer, test writer, build resolver, documentation writer, etc. Each with scoped responsibilities and tools.

2. **150-250 skills loaded on demand**: Avoids context waste by only loading relevant skills per task. Includes language-specific patterns (Next.js, PyTorch, MCP servers). This is the key scalability insight — you can't load everything into every session.

3. **AgentShield security layer**: 1,000+ tests, red-team pipeline using multiple Opus 4.6 agents (Attacker, Defender, Auditor). Agents review each other's output before it reaches production.

4. **Continuous learning system**: Extracts patterns from your sessions, builds confidence scores over time, and automatically applies your conventions. The system gets better the more you use it.

5. **Cross-compatible harness**: Works with Claude Code, Cursor, Codex, OpenCode, Gemini, Zed, GitHub Copilot — same config, different backends. This is brilliant: decouple the agent framework from the model provider.

6. **Verification loops**: Checkpoint + continuous evaluation. Agents don't just produce output — they verify it against tests, linters, and adversarial review before marking tasks complete.

**The Non-Obvious Insight**: Loading skills on-demand (not all at once) is the scalability breakthrough. 150 skills would blow any context window, but by loading only the 3-5 relevant ones per task, ECC stays within token limits while having access to a massive knowledge base. This is exactly how an operating system loads drivers — only when needed.

**What We Can Apply**: This is the scaling pattern for our own skill system. We should structure skills as on-demand modules, not all-loaded-at-once. The AgentShield pattern (adversarial agents reviewing each other) could be applied to our digest pipeline — have a reviewer agent check digest quality before publishing.

## 🔀 Remix Opportunities

### 1. "Obsidian Vault as Agent Context" + Hermes Skills = Vertical Agent Starter Kit
**Combination**: Greg Isenberg's Obsidian knowledge base pattern + ECC's on-demand skill loading + our existing Hermes infrastructure
**The idea**: Build a "Vertical Agent Starter Kit" — a template Obsidian vault pre-loaded with domain research for a specific vertical (e.g., property management, healthcare scheduling), paired with Hermes skills that load on-demand based on task type. Ship it as an installable Hermes skill pack.
**Why non-obvious**: Nobody is packaging domain knowledge + agent skills as a single installable product. Everyone sells either the agent OR the knowledge base, not both together.
**MVP**: Pick one vertical → build the Obsidian vault manually → create 3-5 Hermes skills → package as a skill pack → test with real workflows
**Score**: 16/20 (Novelty: 4, Actionability: 4, Depth: 4, Relevance: 4)

### 2. AgentShield Pattern + Digest Pipeline = Automated Quality Reviewer
**Combination**: ECC's adversarial agent pattern + our Twitter Daily Digest pipeline
**The idea**: Add a "Reviewer Agent" to our digest pipeline that evaluates each day's digest output before commit. Scores depth, checks for named sources, flags surface-level content, and rejects shallow output. If rejected, triggers a rewrite.
**Why non-obvious**: Most content pipelines just publish whatever the agent produces. Adding an adversarial reviewer creates a quality gate that improves over time as the reviewer learns what "good" looks like.
**MVP**: Create a Hermes skill with review criteria → run it as a post-generation step in the digest cron job → if score < threshold, regenerate with reviewer feedback
**Score**: 18/20 (Novelty: 4, Actionability: 5, Depth: 4, Relevance: 5)
