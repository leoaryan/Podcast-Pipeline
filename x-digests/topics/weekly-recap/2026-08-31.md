## Items worth Aryan's time

**Source:** @HermesWatcher (https://x.com/HermesWatcher/status/2091982635677757714 and follow-ups)
**What happened:** Hermes cron jobs now load the agent's full persistent memory on start and can persist learnings across runs. One cron can chain agents via direct handoffs (e.g., Monitoring → Research Bot → Specialist → Writer → Reviewer) using Bot Chat as shared workspace and the message_agent tool.
**Why it matters:** Solves the "forgetting" problem on recurring tasks and moves from isolated agents to reliable, unsupervised team-like systems that maintain continuity and formatting preferences.
**Route:** Build
**Next smallest action:** Review the cronjob tool definition in the daily-digest-systems skill and test one memory-persistent job on an existing lane.

**Source:** @mattpocockuk (https://x.com/mattpocockuk/status/2094156122441625770)
**What happened:** Shared /implement-spec skill: multi-agent system that runs codebase research in subagents, implements tickets concurrently, reviews output against the spec, and cleans up. Positioned as high-leverage AFK workflow while tokens remain cheap.
**Why it matters:** Concrete pattern for turning one-off agent calls into a reliable, spec-driven implementation pipeline that most people still lack.
**Route:** Build
**Next smallest action:** Prototype a similar subagent research + concurrent implement loop for one small internal task.

**Source:** @adocomplete (Anthropic) (https://x.com/adocomplete/status/2094145795276873891)
**What happened:** New /design skill integrates Claude Design’s artboard workflow into CLI and Claude Code Desktop (artifacts-based). User gives a brief; it generates an editable canvas of UI artboards; user picks/tweaks one and Claude implements it. Video demo available.
**Why it matters:** Brings visual design iteration out of the browser into a code-native loop with direct handoff to implementation.
**Route:** Build / Design
**Next smallest action:** Test the skill on a small UI component if access is available, or note the pattern for future Claude Code workflows.

**Source:** @SCR01111 (https://x.com/SCR01111/status/2093718846167495144) and related routing discussion
**What happened:** LLMRouter open-source framework for developing/evaluating/deploying routers (KNN, SVM, MLP, graph-based, multi-turn, multimodal, personalized, agentic). Includes xRouteBench benchmark; learned routers delivered 14.6% relative improvement over strong fixed-model baselines. Cost-aware selection and routing memory emphasized.
**Why it matters:** Shifts the question from “which LLM is best?” to “which LLM + harness is best for this request?” with measurable gains and production concerns (capacity, policy, optimization) beyond simple switching.
**Route:** Learn / Scout
**Next smallest action:** Clone LLMRouter and run the benchmark on one routing decision relevant to current agent jobs.
