## 🔬 Methodology Deep Dives

### 1. Maryam Miradi’s 9-Step Production Agent Workflow (@MaryamMiradi)
**Source**: https://x.com/MaryamMiradi/status/2063351573690872005 (June 6, 2026)

**What they built**: A repeatable engineering discipline for shipping production-grade AI agents (400+ built) using Claude Code, rejecting the "just ask the LLM to build it" approach.

**Step-by-step methodology**:
1. **BMAD Planning** — Start with the *work*, not the code. Use skills like `/pm` + `/analyst` to define user, task, constraints, success metrics, edge cases, and guardrails first.
2. **CLAUDE.md** — Write blunt, specific, concrete rules *before* any files. One good rule can prevent hours of looping mistakes.
3. **/CLEAR + Plan Mode** — Clear stale context, then force a plan/review of flow, tools, and schemas before any coding.
4. **Structured Inputs & Outputs** — Use Pydantic/JSON schemas. Make tools behave like proper APIs. Never accept free-form output.
5. **Skills, Tools & MCP** — Reuse existing skills and MCP servers aggressively. Connect context once instead of pasting docs.
6. **Sub-Agents & Worktrees** — Split responsibilities (research/build/test). Use separate git worktrees and run in parallel safely.
7. **Hooks** — Automatically run tests, schema checks, linting, and permission guards. Block risky actions.
8. **Memory & RAG Skills** — Use trusted memory reviewers and RAG engines (e.g. Memo0, antigravity skills) instead of letting the model hallucinate context.
9. **/evals-create-suite** — Generate proper eval suites *before* shipping. Measure happy paths, failures, and regressions. No “looks good.”

**Tool stack**: Claude Code, Pydantic, MCP servers, git worktrees, custom skills/hooks, eval suites.

**Architecture decisions**: Production agent building is **Plan → Structure → Build → Isolate → Guardrail → Ground → Evaluate**. Sub-agents and worktrees for isolation; hooks for safety; structured schemas everywhere.

**Non-obvious insight**: The LLM is the *easy* part. The real work is in planning, structured engineering, orchestration, memory, guardrails, and rigorous evaluation. “Just ask Claude to build it” produces fragile agents. Disciplined architecture produces production ones. One good CLAUDE.md rule prevents hours of looping.

**What we can apply directly**: Adopt the 9-step sequence as our default agent-building playbook. Prioritize CLAUDE.md + structured schemas + eval suites + MCP reuse. Score: Novelty 4, Actionability 5, Depth 5, Relevance 5 (Total 19/20)

### 2. 8-Layer Agent Architecture Blueprint (@AIandTechh87)
**Source**: https://x.com/AIandTechh87/status/2062560180118925685

**What they built**: High-level systems engineering roadmap framing AI agents as layered production systems.

**The 8 layers**:
1. Define the Purpose (use case, metrics — most projects fail here)
2. System Prompt Design (agent’s *operating system*)
3. Choose the Right LLM (task-matched)
4. Tools & Integrations (what makes it actionable)
5. Memory Systems (working + vector + episodic)
6. Orchestration (workflows, triggers, retries, multi-agent)
7. User Interface (determines success)
8. Testing & Evaluations (quality, latency, reliability)

**Non-obvious insight**: AI Engineering in 2026 = Software Engineering + Prompting + Systems Design + Automation. Orchestration and memory separate chatbots from intelligent agents.

**What we can apply directly**: Use as checklist for any new agent project. Score: Novelty 3, Actionability 5, Depth 4, Relevance 5 (Total 17/20)

## 🧱 Component Discoveries

### 1. Cairn — Structured Log Adapter MCP Server
**Source**: https://github.com/Appwood/cairn-mcp (announced ~June 2026)
**What it does**: Tiny Python MCP server giving coding agents safe, read-only, redacted access to existing structured logs (JSONL, SQLite, Postgres backends) without pasting snippets or leaking secrets.
**Why it matters**: Solves the "agents can't debug runtime without leaking secrets or hallucinating context" problem. Redaction happens before any content leaves the process; read-only by construction; bounded queries + keyset pagination.
**Compatibility surface**: Works with any MCP-enabled agent (Claude Code, etc.). Pluggable backends, 4 read-only tools (search_logs, get_log_detail, etc.).
**Adoption signals**: New but detailed safety-focused design; active discussion on X.
**Non-obvious insight**: The hard 20% (secrets redaction pre-context, lossless multi-source pagination, read-only enforcement) that quick one-off MCPs skip.

**GitHub**: https://github.com/Appwood/cairn-mcp
Score: Novelty 4, Actionability 5, Depth 4, Relevance 5 (Total 18/20)
