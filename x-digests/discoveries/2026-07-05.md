- **OpenOPC** (https://github.com/HKUDS/OpenOPC): Open-source framework for building fully autonomous "AI-native companies." Automatically spins up role-specific AI employees, structures them into orgs, runs multi-agent workflows (task assignment, handoffs, peer reviews, closed loops), and converts completed tasks into reusable organizational knowledge for continuous improvement. Strong signal (294 likes). Next step: Clone repo, read architecture/README, run a minimal example or map the agent orchestration primitives.
- **Multi-role agent engineering workflow** (detailed in https://x.com/PaulSolt/status/2073503459345658037 and related): Treats AI coding agents as a managed software team with dedicated threads/roles (Human Owner, Manager loop for coordination/delegation, Worker for scoped changes + tests + PR prep, QA for independent proof via exact SHAs/artifacts, Reviewer/CI). Includes AI_ENGINEERING_WORKFLOW.md, AGENTS.md, LEARNINGS.md for rules/post-mortems, heartbeat reports, and stuck-thread recovery. Philosophy: accountability + exact proof + institutionalized learnings. Next step: Read full thread + linked artifacts; adapt the manager/worker/QA prompts and test on a small coding task.
- **Karpathy LLM Wiki / Obsidian Second Brain pattern**: Feed raw sources (PDFs, transcripts, notes, repos) into a folder; LLM extracts concepts and builds a persistent, linked Markdown wiki (one page per concept with Obsidian [[wiki-links]]). Knowledge compounds over time. Implementation via Claude + Obsidian plugin (`claude-obsidian`). Portable Markdown output works with other models/agents. Highly discussed with comparisons (e.g., Fable 5 vs. Claude). Next step: Set up Obsidian + plugin in a test folder, run the /wiki flow on a small set of sources, evaluate the resulting graph.
- **Policy-based dynamic model routing + observability traces**: Define policies (cost, capability, latency, fallbacks) instead of hardcoding models. System selects at runtime with full replayable traces (candidates, decisions, latency, cost, hops). Moves from static to optimized, auditable execution. Complements treating LLM calls as distributed-system dependencies (retries, circuit breakers, state machines). Next step: Sketch a minimal policy router + trace logger in code (or find referenced implementations); test routing across 2-3 models on sample requests.
- **Self-supervised tool-use training loop** (from referenced paper): Model proposes tool calls in text; execute and insert results; retain only calls that reduce next-token loss (self-supervised filter); fine-tune on cleaned data. At inference, model emits call token, executes, continues. Works across calculators, search, translators. Next step: Locate the paper/thread, understand the 5-step loop, prototype a tiny version or evaluate feasibility on an existing tool-calling setup.
