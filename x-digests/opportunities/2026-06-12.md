## 🔬 Methodology Deep Dives

### 1. Structured Agent Workflows & Skills Packages (from multiple 2026 builder threads, e.g. https://x.com/i/status/2037250422403113188)
**Who**: Synthesized from high-engagement "how I built" threads by builders using Anthropic/OpenAI SDKs.
**What they built**: Production-grade agent systems starting with deterministic workflows before full agents.
**Step-by-step methodology extracted**:
1. Define the Job with 4 questions: Outcome, Information needed, Allowed actions, Rules.
2. Use AI to design the agent spec (role + goal + tools + rules + output format + 10 test cases).
3. Choose stack: Anthropic Claude Agent SDK for file/shell/web/coding; OpenAI Agents SDK for production handoffs/guardrails.
4. Structure as Role + Goal + Tools + Rules + Output Format.
5. Add tools only if model cannot do alone; describe when/how to use with examples.
6. Memory: Start with none; add short-term history first, then RAG or post-task reflection only when needed.
7. Test ruthlessly with real messy inputs; fix order: prompt clarity → output format → examples → tools → memory.
8. Add reflection/guardrails (self-critique, LLM-as-judge, human-in-loop).
**Tool stack**: Claude/OpenAI SDKs + MCP tools + Skills (markdown packages with YAML frontmatter).
**Architecture**: ReAct loop (input → reason → tool or respond → feedback) + 5 patterns (Prompt Chaining, Routing, Parallelization, Orchestrator-Workers, Evaluator-Optimizer). Later layer: Skills as reusable expert methodology packages loaded progressively.
**Non-obvious insight**: Context engineering (role/rules/examples/skills) > raw model intelligence; workflows beat agents for 70-80% of tasks; "more agents" is usually wrong — simplicity + tool design + reflection wins.
**What WE can apply directly**: Adopt the Skills pattern immediately in Hermes (markdown skill.md files); prioritize the 5 workflow patterns in our cron agents; start every new agent with the 4-question job definition + ruthless real-input testing. Score: 18/20 (Novelty 4, Actionability 5, Depth 5, Relevance 4)

### 2. Autonomous Multi-Agent "Company" with Closed Loops (https://x.com/i/status/2020272022417289587)
**Who**: Solo builder running fully autonomous content/social/analysis/research agents.
**What they built**: Perpetual multi-agent system with 4 DB tables (proposals → missions → steps → events), 5-min heartbeat cron, memory distillation, dynamic agent relationships, initiative system.
**Step-by-step**:
1. Start minimal (3 agents: coordinator, executor, observer).
2. Everything through one proposal service with DB-stored gates/quotas/policies.
3. Distill memory after conversations/outcomes into insights/patterns/lessons/strategies (probabilistic influence ~30%).
4. Add agent personalities/affinity that evolve; run performance reviews (tweet reviews, mission post-mortems).
5. Use simple stack: Next.js + Supabase + VPS ($8/mo) + LLM calls.
**Tool stack**: Supabase (DB), cron heartbeat, structured memory over raw history, skills/runbooks.
**Architecture**: Database-driven closed loop with proposal gates, memory distillation, emergent relationships, pixel-art UI for transparency.
**Non-obvious insight**: Treat agents like employees (SOPs, reviews, relationships, initiative) rather than tools; the "only human inside" model works when memory + rules + proposal gates create self-improving loops.
**What WE can apply directly**: Add proposal/gate + memory distillation layer to Hermes cron jobs; implement agent "reviews" and initiative for our scheduled scans. Score: 17/20

### 3. Markdown + Git Second Brain for Agents (Paweł Huryn @PawelHuryn https://x.com/PawelHuryn/status/2057218125137850409)
**Who**: PM tooling builder who open-sourced sibling to pm-skills.
**Methodology**: Simple folder of markdown files in git repo as agent memory. Agent reads context before answering, writes updates after, weekly sweeps. No vector DB — just grep-able markdown.
**Non-obvious insight**: Inspectable, version-controlled plain files outperform embeddings for many agent memory needs; simplicity enables human review and git workflows.
**What WE can apply directly**: Replace or augment vector memory in Hermes with git-backed markdown skills/knowledge base. Score: 15/20
