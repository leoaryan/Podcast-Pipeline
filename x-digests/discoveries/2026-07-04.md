## Investigate
- **codex-plugin-cc (multi-agent terminal workflow)**: Official OpenAI plugin allowing Codex to run directly inside Claude Code in one terminal. Enables delegating tasks like reviews, adversarial analysis, bug rescue between models without switching contexts. Genuine cross-lab (OpenAI + Anthropic) agent orchestration in a practical CLI setup. Strong candidate for learning real multi-agent patterns beyond single-model prompting.  
  Link: https://x.com/HeyAnjula/status/2073274764572180913  
  Next step: Explore the plugin repo/details, test a sample workflow, compare to single-agent baselines.

- **FrugalGPT cost optimization playbook (routing + caching + adaptation)**: Stanford-derived framework using prompt adaptation (shorter/shared prompts), LLM approximation/caching for repeats, and cascade routing (cheap model first, escalate on low confidence). Claims 98% GPT-4 cost reduction on financial tasks while matching or exceeding quality. Directly applicable to agent workflows.  
  Link: https://x.com/Blum_OG/status/2073047630440169644  
  Next step: Read the underlying paper or implement a simple routing/caching prototype in a local agent loop.

- **pydantic-deepagents (Python multi-agent framework + CLI)**: Open-source self-hosted terminal AI assistant and Pydantic-based framework supporting tool-calling, sandboxed execution, multi-agent teams, skills, checkpoints, unlimited context. Works with any model; inspired by Claude Code but extensible. Repo available for inspection.  
  Link: https://github.com/vstorm-co/pydantic-deepagents (via https://x.com/Kacper95682155/status/2073009876423389263)  
  Next step: Clone repo, review architecture, run a basic multi-agent example.

- **Metabigor (Go CLI OSINT toolkit)**: New open-source command-line reconnaissance tool focused on infrastructure intelligence (ASN/CIDR mapping, CT subdomains, Shodan enrichment, GitHub secret searches, CDN/WAF detection) with minimal API keys, local DBs, batch processing, multiple output formats. Real design philosophy around offline/local-first recon.  
  Link: https://x.com/VivekIntel/status/2073290167134167096  
  Next step: Review source or install and test on a sample target to evaluate practicality vs. existing tools like Amass/Subfinder.

- **MCP Server Architecture Patterns for LLM tool use**: Paper-derived guidelines for designing Model Context Protocol servers that LLMs actually use effectively: group by purpose, keep tool lists small (<10-15), clear plain-language descriptions, avoid monolithic/unsafe/long-running tools. Addresses common LLM confusion with tool overload.  
  Link: https://x.com/rohanpaul_ai/status/2072499557712507190  
  Next step: Study the patterns, apply to building or refactoring a small MCP server or tool-calling setup.
