## 🔬 Methodology Deep Dives

### 1. Jack Culpan's Agent Coding Workflow (Solo Software Engineer)
**Source**: @JackCulpan https://x.com/JackCulpan/status/2029478582352003150

**What they built**: A reliable, self-improving system for working with AI coding agents (primarily Claude Code) on complex projects.

**Step-by-step methodology extracted**:
- Default to "Plan Mode" for any task with 3+ steps or architectural decisions. Re-plan immediately on failure.
- Use liberal subagents: one task per subagent for research, exploration, parallel work.
- After every correction or fix, update `tasks/lessons.md` with the pattern/rule discovered to prevent repeats. Review lessons at the start of every new session.
- Maintain `tasks/todo.md` with: high-level plans, verification checkpoints, progress tracking, summaries, review sections, and lessons capture.
- Verification rule: Never mark a task complete without proof (tests, logs, diffs). Ask "Would a staff engineer approve this?"
- Core principles enforced: Simplicity first, root-cause fixes only, minimal-impact changes, demand elegance where it matters.

**Tool stack**: Claude Code (or similar), git-based markdown task files (no fancy DBs), manual review loops.
**Architecture**: Human + AI as junior/mid engineer with explicit training loop via lessons.md. Code-driven orchestration where possible.
**Non-obvious insight**: The biggest lever is not better prompts but a persistent, grep-friendly knowledge base of past failures that the human (and future agents) reviews every session. This compounds reliability faster than any single model improvement.
**What we can apply directly**: Adopt the `tasks/lessons.md` + `todo.md` pattern in Hermes Agent workflows for persistent improvement tracking. Score: 18/20 (Novelty 4, Actionability 5, Depth 5, Relevance 4)

### 2. 8-Layer Production Agent Blueprint (widely referenced architecture)
**Source**: Multiple threads including @rosemoni18 https://x.com/rosemoni18/status/2061738273169617204 and @elora_khatun

**Methodology**:
1. Define Purpose (use case, metrics, constraints) — most projects fail here.
2. System Prompt Design (treat as OS: role, goals, guardrails).
3. Choose LLM (match to task: tool-use vs reasoning).
4. Tools & Integrations (APIs, MCP, custom tools).
5. Memory Systems (working + vector + episodic + structured).
6. Orchestration (workflows, triggers, queues, retries, multi-agent routing) — the most ignored layer.
7. User Interface (chat, Slack, API, dashboard).
8. Testing & Evaluations (quality, latency, hallucinations, reliability).

**Non-obvious insight**: In 2026, "AI engineering" is Software Engineering + Systems Design. Orchestration and memory separate one-shot chatbots from reliable production systems; model choice is secondary.
**What we can apply directly**: Use this as a checklist when extending Hermes Agent capabilities (especially layers 5-6).
Score: 17/20

### 3. Paweł Huryn's Markdown Second Brain + Weekly Sweep
**Source**: @PawelHuryn (pm-skills sibling repo, 11k+ stars context) https://x.com/i/status/2057218125137850409

**Methodology**: Git repo of markdown files as memory layer. Agent reads relevant files before answering, writes updates after. Runs a weekly sweep to surface contradictions (strategy vs opinion) instead of forcing consensus. No embeddings or vector DB — everything remains grep-friendly and human-auditable.
**Non-obvious insight**: Contradiction surfacing + simple git primitives beats complex RAG for long-term personal/productivity agents because it preserves nuance and allows easy human intervention.
**Tool stack**: Git + markdown folders + custom agent that does read/write + weekly cron sweep.
Score: 16/20
